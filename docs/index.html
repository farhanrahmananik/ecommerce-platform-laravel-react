02 / What was built

Two experiences.
One source of truth.

The repository contains two focused applications: React owns the interaction layer; Laravel owns validation, business rules, persistence, and authorization.

01

Customer commerce

From public discovery to authenticated post-purchase actions, with intentional loading, error, empty, and mobile states.

  • Search, filter, sort, and paginated catalog
  • Product galleries, pricing, stock, and approved reviews
  • Stock-aware cart and coupon validation
  • Cash-on-delivery checkout and order snapshots
  • Order history and verified-purchase reviews
02

Store operations

A role-protected workspace for the workflows behind the storefront, from catalog maintenance to operational reporting.

  • Categories, products, images, and availability
  • Stock adjustments and movement history
  • Coupons, orders, and controlled status transitions
  • Review moderation and operational reports
  • Filterable audit logs with before/after context

Authorization boundary

Super Admin, Store Manager, Admin, and Customer are implemented role values. Admin access uses a role field and custom middleware; the project does not claim a separate fine-grained permission system.

03 / Product flows

The customer path stays legible.

Each stage exposes the context and feedback a customer needs, while the API re-checks sensitive state before committing a purchase.

  1. 01DiscoverSearch, category, featured, sorting, pagination
  2. 02EvaluateGallery, price, inventory, approved reviews
  3. 03PurchaseCart, coupon, delivery, billing, checkout
  4. 04ReturnOrder history and verified-purchase reviews

Commerce integrity

  • Server-side stock validation
  • Coupon rule enforcement
  • Transactional order creation
  • Row locking around sensitive writes

04 / Operations

The other half of commerce.

The admin workspace turns application state into daily operational tools instead of treating administration as a collection of disconnected CRUD screens.

Catalog

Category, product, image, pricing, featured, and visibility controls.

Inventory

Stock adjustments with movement history and inventory reporting.

Fulfillment

Order search, details, and controlled status workflow.

Intelligence

Sales, top-product, stock, review, and audit views.

05 / Architecture

Responsibilities have an address.

The architecture keeps HTTP concerns, business rules, response shaping, API access, and UI state in distinct, predictable layers.

01 / Interface

React SPA

Pages, reusable components, route guards, auth and cart contexts.

Axios→
02 / HTTP

Laravel API

Thin controllers, Form Requests, middleware, Resources and collections.

Eloquent→
03 / Domain

Services + data

Business rules, transactions, row locks, relationships, and audit history.

Auth

First-party SPA sessions

Sanctum cookie authentication with CSRF protection; authenticated and admin routes enforce separate boundaries.

API design

Stable response shapes

API Resources isolate JSON contracts while Form Requests centralize payload and filter validation.

Consistency

Critical writes stay atomic

Transactions and targeted row locks protect cart, checkout, coupon, stock, review, and order workflows.

Traceability

Important actions leave context

Audit logging captures relevant changes without moving that responsibility into controllers.
